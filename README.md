# Santa Amiga (EN через ES)

Дуже простий pet-проєкт для мами: mobile-first веб-апка для вивчення англійської через іспанську.

## Що тут є

- Назва: **Santa Amiga**
- Візуальний стиль: натхнення естетикою Santa Muerte
- Маскот-помічниця **Санта Аміґа** (дає підказки EN через ES)
- 2 головні дії: слово дня + міні-квіз

## ВАЖЛИВО: ЧОМУ ФАЙЛІВ МОЖЕ НЕ БУТИ НА GITHUB

Якщо ти бачиш файли в Codex, але не бачиш їх на GitHub — це нормально.
Причина: зміни збережені локально, але ще **не запушені** в GitHub-репозиторій.

Що треба зробити:

1. Додати remote (один раз):
```bash
git remote add origin <URL_твого_GitHub_репозиторію>
```
2. Запушити гілку:
```bash
git push -u origin work
```
3. Після цього онови сторінку GitHub — файли з'являться.

> Якщо remote вже є, перший крок пропускаєш і робиш тільки `git push -u origin work` (або просто `git push`).

## ДЕ САМЕ ВІДКРИТИ ТЕРМІНАЛ (ДУЖЕ ВАЖЛИВО)

Тобі потрібен **термінал у VS Code** (не на GitHub-сайті).

Куди тиснути (Mac, як на твоєму скріні):

1. Відкрий VS Code.
2. Якщо не бачиш верхнє меню — наведи курсор миші в самий верх екрана (menu bar macOS з'явиться).
3. У menu bar натисни **Terminal**.
4. Натисни **New Terminal**.
5. Внизу відкриється чорне/темне вікно — це і є термінал.
6. Саме сюди вставляєш команди `git ...` і тиснеш Enter.

Якщо меню не видно або незручно, використовуй гарячі клавіші:

- **Control + `** → відкрити/сховати термінал.
- **Command + Shift + P** → введи `Terminal: Create New Terminal` → Enter.

## ГОЛОВНЕ ПИТАННЯ: "ТРЕБА ВИКАЧУВАТИ ФАЙЛИ ЧИ ПІДКЛЮЧАТИ GITHUB?"

Коротка відповідь: **так, тобі потрібні файли проєкту на твоєму комп'ютері**.

Є 2 прості варіанти:

### Варіант А (найпростіший): скачати ZIP

1. Відкрий репозиторій на GitHub.
2. Натисни зелений кнопка **Code**.
3. Натисни **Download ZIP**.
4. Розпакуй ZIP у зручну папку.
5. Цю папку потім відкриваєш у VS Code.

### Варіант Б (кращий на майбутнє): через git clone

1. Встанови Git: https://git-scm.com/downloads
2. Відкрий термінал.
3. Виконай:

```bash
git clone <URL_твого_репозиторію>
```

4. Зайди в папку:

```bash
cd <назва_папки>
```

5. Відкрий VS Code у цій папці:

```bash
code .
```

> Якщо ти взагалі перший раз — бери **Варіант А (ZIP)**. Це найменше стресу.

## PUSH НА GITHUB СУПЕР-ПРОСТО (КОПІЮЙ-ВСТАВ)

### Крок 1: відкрити термінал у VS Code
- Варіант 1: menu bar macOS → **Terminal** → **New Terminal**.
- Варіант 2: натисни **Control + `**.

### Крок 2: перевірити remote
Встав і натисни Enter:

```bash
git remote -v
```

### Крок 3: якщо після команди ПУСТО — додай свій GitHub URL

```bash
git remote add origin <URL_ТВОГО_РЕПО>
```

### Крок 4: запуш файли (в правильну гілку)

1) Дізнайся назву своєї гілки:
```bash
git branch --show-current
```
2) Пушни саме цю гілку (приклад для `main`):
```bash
git push -u origin main
```

### Крок 5: перевір GitHub
- Відкрий сторінку репозиторію в браузері.
- Натисни refresh.
- Файли мають з'явитись.

## КОЛИ ВИЛІЗАЄ ПОМИЛКА `src refspec work does not match any`

Це означає: ти зараз **не на гілці `work`** або ще **нема коміту**.

На твоєму скріні видно, що ти на `main`, тому команда з `work` ламається.

Роби рівно так:

1. Перевір гілку:
```bash
git branch --show-current
```

2. Якщо показує `main`, пуш у `main`:
```bash
git push -u origin main
```

3. Якщо скаже, що нема що пушити, спершу зроби перший коміт:
```bash
git add .
git commit -m "first commit"
```

4. І знову пуш:
```bash
git push -u origin main
```

## ЯКЩО ПІСЛЯ PUSH ПИШЕ `Everything up-to-date`, А ФАЙЛІВ НЕМА

Це означає: у локальній гілці нема нових комітів з файлами.

Зроби ось так (копіюй-встав):

1) Перевір статус:
```bash
git status
```

2) Якщо бачиш `Untracked files` або `Changes not staged`, додай файли:
```bash
git add .
```

3) Створи коміт:
```bash
git commit -m "add project files"
```

4) Запуш у GitHub:
```bash
git push
```

5) Онови сторінку репозиторію на GitHub (F5).

## ЯКЩО `git status` ПОКАЗУЄ `working tree clean`, А ТИ ЧЕКАВ НОВІ ФАЙЛИ

Це значить: у твоїй локальній папці зараз нема нових змін.

Важливий момент: якщо файли створювались в іншому середовищі (наприклад, окремо в Codex),
вони **не з'являться автоматично** у твоїй папці на Mac, доки ти їх не перенесеш/створиш тут.

Найпростіший шлях для старту:

1. У VS Code в папці `amiga` створи 4 файли:
   - `index.html`
   - `styles.css`
   - `app.js`
   - `README.md`
2. Встав у них код.
3. Збережи (`Cmd + S`).
4. Виконай:
```bash
git add .
git commit -m "add santa amiga app files"
git push
```

## СТАРТ З НУЛЯ (якщо ти взагалі вперше)

### Крок 0. Встанови VS Code

1. Відкрий сайт: https://code.visualstudio.com/
2. Натисни кнопку **Download**.
3. Встанови програму як звичайний застосунок.
4. Відкрий VS Code.

### Крок 1. Відкрий папку проєкту

1. У VS Code натисни **File → Open Folder...**
2. Обери папку з цим проєктом (де лежать `index.html`, `styles.css`, `app.js`).
3. Натисни **Open**.

### Крок 2. Встанови розширення Live Server

1. Зліва натисни іконку **Extensions** (квадратик).
2. У пошуку введи: `Live Server`.
3. Вибери **Live Server (by Ritwick Dey)**.
4. Натисни **Install**.

### Крок 3. Запусти сайт (де саме запускати `index.html`)

1. У лівій панелі VS Code натисни файл **`index.html`**.
2. Внизу праворуч натисни кнопку **Go Live**.
3. Відкриється вкладка браузера з сайтом.

### Крок 4. Якщо кнопки Go Live НЕМАЄ

1. У VS Code натисни **Terminal → New Terminal**.
2. Внизу відкриється термінал.
3. Введи команду:

```bash
python3 -m http.server 5173
```

4. Натисни Enter.
5. Відкрий браузер і встав адресу: `http://localhost:5173`

## План розробки продукту Santa Amiga (без хаосу)

Нижче — практичний план, щоб не стрибати між дизайном/кодом/фічами.

### Принцип порядку робіт

1. **Продуктова рамка** (для кого, навіщо, результат).
2. **MVP-флоу** (мінімум екранів і сценаріїв).
3. **Дані та архітектура** (що зберігаємо і як пов’язано).
4. **UI/UX для мобілки**.
5. **Логіка і стан прогресу**.
6. **Контент і уроки**.
7. **Аналітика і ітерації**.

---

### Етап 0 — Product Scope (1 день)

Зафіксувати в 1 сторінці:

- Persona: україномовний користувач, вже знає іспанську.
- Ціль: вчити EN через порівняння з ES.
- Time-to-value: перша корисна практика за 60 секунд.
- Success metric MVP: 5 сесій/тиждень і 20 слів у вивченні.

---

### Етап 1 — MVP v1 (1 тиждень)

Обов’язкові фічі:

- Слово + ES-пояснення + підказка маскота.
- Кнопки: “Знаю” / “Не знаю”.
- Міні-квіз EN↔ES.
- Локальне збереження прогресу (`localStorage`).
- Простий екран “Мій прогрес” (скільки слів вивчено).

Не робимо в MVP:

- акаунти,
- бекенд,
- складна гейміфікація,
- AI-чат.

---

### Етап 2 — Архітектура фіч (перед масштабом)

Рекомендований поділ модулів:

- `content/` — словник, набори слів, теми.
- `learning/` — алгоритм повторень (черга слів, інтервали).
- `quiz/` — генерація питань, перевірка відповідей.
- `progress/` — збереження і статистика.
- `ui/` — картки, кнопки, прогрес-екрани.
- `mascot/` — тексти-підказки і тон голосу.

Поки без бекенду це можна тримати як JS-модулі + JSON.

---

### Етап 3 — Модель даних (мінімальна)

`word`:
- `id`
- `en`
- `es`
- `note`
- `hint`
- `topic`
- `level`

`userProgress`:
- `wordId`
- `status` (`new` / `learning` / `known`)
- `correctStreak`
- `lastSeenAt`
- `nextReviewAt`

Зв’язок: `word.id` ↔ `userProgress.wordId`.

---

### Етап 4 — Технічна послідовність (правильний порядок)

1. Нормалізувати структуру файлів (під модулі).
2. Винести словник у окремий JSON/JS файл.
3. Додати шар `storage` (читання/запис `localStorage`).
4. Додати шар `state` (поточне слово, індекс, статистика).
5. Додати `learning engine` (простий інтервал повторення).
6. Додати прогрес-екран.
7. Лише потім — нові “красиві” фічі.

---

### Етап 5 — UX/Контент система

- Теми пакетами по 20 слів: daily life, shopping, health, travel.
- Для кожного слова: 1 приклад речення + 1 типова помилка (false friend).
- Маскот дає короткі фрази підтримки, а не довгі тексти.
- На мобілці: великі тап-зони, мінімум полів, 1 головна дія на екран.

---

### Етап 6 — Roadmap розвитку

**v1.1**
- streak (дні підряд),
- добова ціль (5/10/15 слів),
- фільтр “помилки дня”.

**v1.2**
- аудіо вимова (TTS),
- режим “тільки важкі слова”,
- міні-діалоги EN через ES.

**v2**
- акаунт + синхронізація між девайсами,
- бекенд і хмарний прогрес,
- персоналізований план навчання.

---

### Що робимо прямо зараз (наступний спринт)

1. Зафіксувати MVP-скоуп письмово (без нових фіч).
2. Додати `localStorage` для `known/learning` статусів.
3. Додати екран “Прогрес”.
4. Додати перші 20 слів по темі `daily life`.
5. Зробити 1 демо-прохід: 5 хвилин навчання від старту до прогрес-екрану.
